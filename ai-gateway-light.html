TRY / MODEL ROUTING

障害時は、

AI Gateway / AI Agent
03.3 / AGENT-TO-AGENT

専門agentへの依頼にも、入口と統制を。

別のagentへ仕事を任せる通信を、中継・保護・観測する。

AGENT ACCESS / ILLUSTRATIVE

Cardの書換えと、上流への直接到達を防ぐ設計は別です。

TRY / DELEGATION FLOW

何ができるagentかを知る。

Agent Cardで能力と入口を確認。Gatewayの入口を案内します。

依頼を届ける前に、権限を確認。

認証と許可ルールを適用し、委譲先へ要求を中継します。

仕事の状態を、通信から把握。

Taskの状態、エラーや遅延を観測。仕事を進めるのは専門agentです。

結果を受け取り、次の判断へ。

出力はArtifact等で返却。短い対話では即時Messageで返る場合もあります。

許可のない依頼は入口で止める。

agentや利用者の権限に合わせ、専門agentへのアクセスを制御します。

説明用の進行。Gatewayはagentの計画・仕事の実行・Task状態管理を代行しません。

THE APPROACH

仕事は専門agentへ。接続の統制はAI Gatewayへ。

03.4 / SHARED GOVERNANCE

守る。抑える。把握する。

共通の運用観点を持ち、通信ごとの違いを見落とさない。

01

守る

誰が、どの接続先を使えるか。認証・権限・必要な情報保護を適用する。

Identity / Access / Protection

02

抑える

利用者や用途ごとに、要求の量と使い方を制御する。

Quotas / Rate limits / Policies

03

把握する

要求、エラー、遅延を追い、通信の種類に合う指標を見る。

Usage / Errors / Latency

LLM：tokens・費用等 ／ MCP：tool呼出等 ／ A2A：operation・Task等。取得できる指標は採用版・設定・通信内容によります。

THE APPROACH

共通の基盤で管理し、通信に合うルールと指標を使う。
